# ProjectForge UML correction log

Source audit: October 15, 2026. Scope: six selected implementation views, not a redesign of the software. No application behaviour or repository classes were changed for this correction. Original files are retained in the parent directory; corrected exports and sources are in this directory.

Classification: **CONFIRMED ERROR** identifies an original UML or flow defect. **VERIFIED CORRECTION** records the code-backed replacement. **NEEDS CODE VERIFICATION** is reserved for claims not established by the inspected source; these are not silently promoted to implemented behaviour.

## Source and abstraction notes

- Background and Understanding are function-level participants, not invented Python classes. Code / repo groups CodingAgent, AgentToolContext, RepositoryManager and memory calls to keep A4 readable.
- Sequence messages name actual endpoints; /{id}/... abbreviates /api/projects/{project_id}/.... The already-open SSE connection is separate from POST /analyze and POST /build.
- The provider factory checks configuration before initializing the Gemini SDK, so offline use does not require a Gemini key.
- No user, authentication, planned SQL table, agent superclass, model-client interface or automatic website deployment was added.
- Optional object fields use Optional[...] or multiplicity 0..1 only where the value is an object reference. The serialized BuildSpec dictionary is intentionally not an object association.
- Long parameter lists may wrap or use ellipses in selected class views. All six .puml files remain editable; types shown as dict/List match collection abstraction, not additional classes.

## Deliverable validation boundary
